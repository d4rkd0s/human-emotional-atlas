# Human Emotional Atlas

<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
Implementation delegated to agents: dependency-free HTML, CSS and JavaScript, with static GitHub Pages deployment and a Python build step.

## Users
Humans inspecting emotional knowledge and AI/SI agents reading a public reference dataset.

## Product Purpose
Map emotions, qualities, mixtures, neighboring states, contrasts and contextual transitions so consumers can form their own interpretations.

## Capabilities and Constraints
English initially. Searchable entries, interactive relationship map, readable source context and easy copy-paste instructions for obtaining the dataset. No inference engine. No prescribed emotional response policy. Confidence assessments belong to the private building process. Emotional data loads and changes require human review through pull requests; infrastructure can go directly to main. CC0 original content. Do not present an exhaustive inventory or certain interpretation of an individual.

## Brand Commitments
HEA, Human Emotional Atlas. Sleek, simple, colorful. Seven spectral color families used aesthetically; no spiritual terminology or scientific meaning attached to color.

## Evidence on Hand
Data lives in data/*.json. Counts must be calculated from those files. The site must honestly handle an empty approved dataset and loading failures.

## Product Principles
- Knowledge should remain inspectable and reusable.
- Context and alternative interpretations matter.
- Scientific and contemplative sources keep their provenance.
- Readability and direct access take priority over decoration.
